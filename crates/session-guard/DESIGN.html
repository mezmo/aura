3. Schema + statements S1–S4

CREATE TABLE session_claims (
  session_id       text PRIMARY KEY,
  epoch            bigint      NOT NULL,
  holder_id        uuid        NOT NULL,
  holder_pod       text        NOT NULL,
  lease_expires_at timestamptz NOT NULL,
  manifest         jsonb       NOT NULL DEFAULT '{}',
  last_commit_op   uuid,
  parked_turn      uuid
);
-- never DELETE (I7); READ COMMITTED pinned (PG default);
-- all lease math uses clock_timestamp() (I6)

S1 — claim / steal / reify

INSERT INTO session_claims (session_id, epoch, holder_id, holder_pod,
                            lease_expires_at, manifest, last_commit_op, parked_turn)
VALUES ($1, 1, $2, $3, clock_timestamp() + $4::interval, '{}', NULL, NULL)
ON CONFLICT (session_id) DO UPDATE
  SET epoch            = session_claims.epoch + 1,
      holder_id        = EXCLUDED.holder_id,
      holder_pod       = EXCLUDED.holder_pod,
      lease_expires_at = clock_timestamp() + $4::interval,
      parked_turn      = NULL
  WHERE session_claims.lease_expires_at < clock_timestamp()
    AND (session_claims.parked_turn IS NULL OR session_claims.parked_turn = $5)
RETURNING epoch, lease_expires_at, manifest;

0 rows → one cheap classify SELECT distinguishes Busy (live lease; hint from config) from Parked (parked_turn ≠ $5). Reify: $5 is the parked TurnId — the predicate passes and the latch clears in the same statement.

S2 — heartbeat

UPDATE session_claims
SET lease_expires_at = clock_timestamp() + $4::interval
WHERE session_id = $1 AND epoch = $2 AND holder_id = $3
  AND lease_expires_at > clock_timestamp()
RETURNING lease_expires_at;
-- 0 rows = stolen or expired → revoke (fail closed)

S3 — commit

UPDATE session_claims
SET manifest = $5::jsonb,
    last_commit_op = $6,
    parked_turn = $7
WHERE session_id = $1 AND epoch = $2 AND holder_id = $3
  AND lease_expires_at > clock_timestamp();
-- 1 row = Committed. 0 rows = LostFence.
-- Connection error = commit-unknown → reconcile_commit read-back on last_commit_op (B3).

The per-file write path — why temp + rename survives the Q7 simplification

With the manifest in PG, rename's remaining job is narrow and precise: make "the name exists" ≡ "the content is complete" one atomic event, on a mount where rename is the only vendor-affirmed atomic op and name/content visibility order across clients is otherwise untrustworthy. Without it, a reader can see a name while bytes are still trickling — or a torn file after a crash mid-write — and the ENOENT/mismatch classification stops being sound. It also gives a failed write a clean retry target (fresh temp per attempt; the final path is never half-anything), which keeps I1 literally true. It is not zombie protection (epoch dirs + I1 carry that) and no longer manifest publication (PG carries that).

writer, pre-commit, per file:
  e{k}/.tmp/{name}.{attempt}  ── write full bytes ── fsync(temp) ──rename──►  e{k}/{name}
                                (fresh temp per attempt;   (165–950 ms,      vendor-affirmed atomic:
                                 final path never torn)     concurrent)       name ≡ complete content
then: one S3 UPDATE publishes the manifest (paths + shas) atomically in PG.
open: parent-dir fsync after rename — POSIX recipe; on Archil it's a vendor-semantics question.

5. Named invariants

I1 — Write-once per path. A manifest-referenced file is never opened for write. This is what makes zombie containment complete and demotes digest verification to detection-only.
I2 — holder_id freshness is the second fence. Minted per acquire attempt; commit/heartbeat predicates keep PG linearizing commits even if an async-failover regresses the epoch.
I3 — Epoch-scope GC deletion. A sweep deletes only under epochs strictly below its keep-set's claims-row read. No timing arguments.
I4 — Commit ordering. fsync data files (concurrent) → one atomic S3. The committed manifest never names undurable bytes (manifest-in-PG removes the pointer-flip window by construction).
I5 — Fail-stop on PG-down. No new claims, renewals fail, holders self-fence at lease expiry. No degraded mode.
I6 — clock_timestamp() only for lease math. now() is transaction-start and would reintroduce codex B2 (verified against PG 18 docs, 2026-08-23).
I7 — READ COMMITTED pinned; never DELETE. The steal's WHERE-re-evaluation is documented READ COMMITTED behavior; claim rows live forever so epochs cannot regress on a single primary.

7. Non-goals for rev-12

  • The park algorithm and parked-file selection — HITL-271 owns them; rev-12 only carries the column, the Parked variant, and the same-TurnId reify path.
  • Compaction / summarization / age-based eviction of artifact references — a future card; v1 keeps all committed artifacts.
  • Dead-session retention sweeper — a product TTL decision, not a correctness hole.
  • Migration of any existing state — greenfield.
  • The claim-file adapter — retired by ruling, not re-implemented.
